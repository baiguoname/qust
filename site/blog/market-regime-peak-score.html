市场状态高峰：用 qust 检测期货市场 regime change

项目地址 · git地址

本节介绍 daily_market_change_peak_score：一个面向期货日线长表的市场状态变换高峰检测算子。

它要回答的问题不是“今天涨了吗”，也不是“某个品种是不是突破了均线”，而是：

从整个期货市场的横截面状态看，哪几个日期附近出现了最明显、最不寻常、并且跨多个观察尺度都能看到的结构变化？

这里的“市场状态”不是单一价格序列，而是全市场合约在同一天共同形成的特征分布。一个 regime change 往往不是某一个合约单独变化，而是很多合约的收益、波动、上下行振幅、成交活跃度等特征一起发生变化。daily_market_change_peak_score 就是为了把这种变化压缩成每天一行的分数，并从连续高分里确认少数几个真正的高峰点。

这不是投资建议，也不是一个直接买卖信号。它更适合用来做市场阶段划分、策略分段诊断、样本内外稳定性检查、以及策略参数是否需要分 regime 管理的辅助工具。

1. 为什么需要这种方法

做期货策略分析时，经常会遇到下面几类问题：

  1. 同一个策略在某几年表现很好，换一段历史就明显变差；
  2. 某些年份不是单纯收益变差，而是交易节奏、波动结构、趋势延续性、反转强度一起变了；
  3. 单看某个品种容易误判，因为单品种变化可能只是品种自己的事件，不能代表整个市场；
  4. 简单用收益率均值或波动率做分段，容易被某几个极端合约带偏；
  5. 用固定窗口比较前后两段时，窗口长度一变，分数尺度也会变，导致不同窗口之间不好比较；
  6. 市场结构变化通常会连续几天都给出高分，如果每天都当成一个 regime 点，结果会太密集，无法用于分析。

daily_market_change_peak_score 的设计目标就是解决这些问题：

  • 先把每个合约自己的价格变化标准化，降低不同品种波动水平差异的影响；
  • 再按交易日做横截面聚合，得到每天一行的全市场特征；
  • 用相邻窗口的分布差异，而不是单个均值，衡量前后市场状态是否发生改变；
  • 同时检查多个窗口尺度，让结果不只依赖某一个窗口长度；
  • 用每个尺度自己的历史分布做在线标准化，让不同尺度之间可以比较；
  • 对连续候选峰做间隔确认，只保留一段异常里的最高峰。

所以它输出的不是密密麻麻的“每天变化分数”，而是更适合观察市场阶段切换的稀疏高峰。

2. 算子做了什么

一行调用：

res = col.all.regime.daily_market_change_peak_score().calc_data(data_kline)

输入是一张期货日线长表。每行通常是一根合约日 K 线，至少需要：

字段 含义
ticker 品种名，例如 rb、fu、SA
ct 合约编号，用于区分同一品种下不同合约
datetime K 线时间戳，算子内部会取日期作为交易日
open 开盘价
high 最高价
low 最低价
close 收盘价
volume 成交量

算子内部会按 ticker, ct 隔离每个合约的历史状态，再按 date 聚合成全市场特征。它并不要求用户提前 pivot，也不要求用户手动构造宽表。

默认使用的多尺度窗口是：

[(21, 21), (42, 21), (63, 21), (63, 42), (126, 42)]

例如 63x42 表示：在当前观察日附近，拿切点前 63 个交易日和切点后 42 个交易日进行比较。尺度越短，对快速冲击越敏感；尺度越长，更偏向捕捉持续性的市场结构变化。

3. 计算市场状态高峰

下面是真正的计算代码。默认参数已经比较严格：

  • baseline_window=756：每个尺度最多用约三年历史分数做标准化；
  • min_baseline=126：某个尺度至少积累约半年历史分数后才开始输出 z-score；
  • z_thre=4.0：候选峰的综合强度要明显高于历史常态；
  • rank_thre=0.98：候选峰还要处在同尺度历史分布的极高分位；
  • persistence_thre=0.4：不只一个尺度异常，至少要有一定多尺度一致性；
  • min_peak_distance=90：连续异常不会每天都输出峰，而是在相隔足够远之后确认一段异常里的最高点。

这些约束让输出更稀疏，也更适合拿来做 regime 分析。

4. 输出字段怎么读

daily_market_change_peak_score 每个有效交易日输出一行。可以把输出字段分成四类。

字段 含义
date 当前输出行日期。若 is_peak=True，它是确认日，不一定是真正峰值发生日
cut_date 当前观察日下，最佳尺度估计出的市场结构切换点
prev_start / prev_end 当前最佳尺度左侧窗口的起点和终点
curr_start / curr_end 当前最佳尺度右侧窗口的起点和终点
best_scale 当前观察日贡献最大的尺度，例如 21x21、63x42
prev_n / curr_n 当前最佳尺度左右窗口实际样本数
baseline_n 当前最佳尺度已经累积了多少个历史分数用于标准化
scale_count 当天有多少个尺度成功产出标准化分数
energy_xy 左右两段之间的平均距离
energy_xx 左侧窗口内部平均距离，不含对角线
energy_yy 右侧窗口内部平均距离，不含对角线
energy_score 分布差异主分数，越高说明左右两段整体差异越大
loc_score 均值位置变化解释项
scale_score 离散程度或波动尺度变化解释项
score_raw 当前最佳尺度的原始变化分数
score_z 当前最佳尺度相对自己历史分布的 robust z-score
score_rank 当前最佳尺度在自己历史分布中的在线分位
persistence 多尺度一致性，越高说明越多尺度同时异常
peak_score 当前观察日的最终候选高峰分数
is_peak_candidate 当前观察日是否进入候选峰簇
is_peak 当前行是否确认输出一个稀疏峰
confirmed_date 被确认的真实峰值观察日
confirmed_cut_date 被确认峰对应的估计结构切换点
confirmed_best_scale 被确认峰的最佳尺度
confirmed_prev_n / confirmed_curr_n 被确认峰左右窗口长度
confirmed_score_raw 被确认峰的原始变化分数
confirmed_score_z 被确认峰的 robust z-score
confirmed_score_rank 被确认峰的历史分位
confirmed_persistence 被确认峰的多尺度一致性
confirmed_peak_score 被确认峰的最终强度

最容易误读的是 date、confirmed_date 和 confirmed_cut_date：

  • date 是当前输出行日期；
  • confirmed_date 是真正被选中的峰值观察日；
  • confirmed_cut_date 是算法估计的前后状态分界点。

确认峰需要等待一段距离，所以 is_peak=True 往往晚于 confirmed_date。这是为了避免把未来确认结果回写到过去日期。

5. 用柱状图看确认峰

下面的图只画已经确认的峰。横轴这里用 date，也就是确认输出日；柱子的高度是 confirmed_peak_score。

confirmed_peak_score 越高，表示这个确认峰在历史标准化之后越异常，并且越可能在多个尺度上同时显著。它不是收益率，也不代表方向；它表示“市场状态发生变化的强度”。

实际分析时通常同时看三列：

  • confirmed_peak_score：强度有多高；
  • confirmed_persistence：有多少尺度同时支持这个变化；
  • confirmed_best_scale：这个变化更偏短期冲击还是中长期结构切换。

8. 每个确认 regime 点的解释

下面先整理一张辅助解释表。表里比较的是每个确认峰对应的 prev 窗口和 curr 窗口：

  • abs_ret_ratio：右侧窗口平均绝对收益 / 左侧窗口平均绝对收益；
  • range_ratio：右侧窗口平均日内振幅 / 左侧窗口平均日内振幅；
  • up_ratio_before / up_ratio_after：切点前后上涨合约占比；
  • up_range_ratio / down_range_ratio：上行振幅、下行振幅的前后比值；
  • volume_delta：成交量变化特征的前后差值。

这张表用于解释结果，不替代算子本身。最终 regime 点仍以 confirmed_peak_score 和确认峰输出为准。

peak_windows = (
    res.filter(pl.col("is_peak"))
    .select(
        "date",
        pl.col("confirmed_date").alias("peak_date"),
        pl.col("confirmed_cut_date").alias("cut_date"),
        pl.col("confirmed_best_scale").alias("scale"),
        pl.col("confirmed_peak_score").alias("score"),
        pl.col("confirmed_persistence").alias("persistence"),
    )
    .join(
        res.select(
            pl.col("date").alias("peak_date"),
            "prev_start",
            "prev_end",
            "curr_start",
            "curr_end",
        ),
        on="peak_date",
        how="left",
    )
)

contract_features = (
    data_kline
    .sort(["ticker", "ct", "datetime"])
    .with_columns(
        pl.col("datetime").dt.date().alias("feature_date"),
        pl.col("close").shift(1).over(["ticker", "ct"]).alias("prev_close"),
        pl.col("volume").shift(1).over(["ticker", "ct"]).alias("prev_volume"),
    )
    .with_columns(
        (pl.col("close") / pl.col("prev_close") - 1.0).alias("ret"),
        ((pl.col("high") - pl.col("low")) / pl.col("prev_close")).alias("range_pct"),
        ((pl.col("high") - pl.max_horizontal("open", "close")) / pl.col("prev_close")).clip(0.0, None).alias("up_range_pct"),
        ((pl.min_horizontal("open", "close") - pl.col("low")) / pl.col("prev_close")).clip(0.0, None).alias("down_range_pct"),
        ((pl.col("volume") + 1.0).log() - (pl.col("prev_volume") + 1.0).log()).alias("volume_chg"),
        (pl.col("close") > pl.col("prev_close")).cast(pl.Float64).alias("up_flag"),
    )
    .filter(pl.all_horizontal(pl.col("ret", "range_pct", "up_range_pct", "down_range_pct", "volume_chg").is_finite()))
)

window_rows = (
    peak_windows
    .join(contract_features, how="cross")
    .with_columns(
        pl.when(pl.col("feature_date").is_between(pl.col("prev_start"), pl.col("prev_end")))
        .then(pl.lit("before"))
        .when(pl.col("feature_date").is_between(pl.col("curr_start"), pl.col("curr_end")))
        .then(pl.lit("after"))
        .otherwise(None)
        .alias("side")
    )
    .filter(pl.col("side").is_not_null())
)

side_stats = (
    window_rows
    .group_by("peak_date", "cut_date", "scale", "score", "persistence", "side")
    .agg(
        pl.col("ticker").n_unique().alias("tickers"),
        pl.col("ct").n_unique().alias("contracts"),
        pl.col("ret").abs().mean().alias("abs_ret"),
        pl.col("range_pct").mean().alias("range"),
        pl.col("up_range_pct").mean().alias("up_range"),
        pl.col("down_range_pct").mean().alias("down_range"),
        pl.col("up_flag").mean().alias("up_ratio"),
        pl.col("volume_chg").mean().alias("volume_chg"),
    )
)

key_cols = ["peak_date", "cut_date", "scale", "score", "persistence"]
before = side_stats.filter(pl.col("side") == "before").select(
    *key_cols,
    pl.col("abs_ret").alias("abs_ret_before"),
    pl.col("range").alias("range_before"),
    pl.col("up_range").alias("up_range_before"),
    pl.col("down_range").alias("down_range_before"),
    pl.col("up_ratio").alias("up_ratio_before"),
    pl.col("volume_chg").alias("volume_before"),
)

    *key_cols,
    pl.col("abs_ret").alias("abs_ret_after"),
    pl.col("range").alias("range_after"),
    pl.col("up_range").alias("up_range_after"),

    pl.col("up_ratio").alias("up_ratio_after"),
    pl.col("volume_chg").alias("volume_after"),

regime_notes = (
    before
    .join(after, on=key_cols, how="inner")
    .with_columns(
        (pl.col("abs_ret_after") / pl.col("abs_ret_before")).alias("abs_ret_ratio"),
        (pl.col("range_after") / pl.col("range_before")).alias("range_ratio"),
        (pl.col("up_range_after") / pl.col("up_range_before")).alias("up_range_ratio"),
        (pl.col("down_range_after") / pl.col("down_range_before")).alias("down_range_ratio"),
        (pl.col("volume_after") - pl.col("volume_before")).alias("volume_delta"),
    )
    .with_columns(
        pl.when((pl.col("abs_ret_ratio") >= 1.35) | (pl.col("range_ratio") >= 1.35))
        .then(pl.lit("波动明显放大"))
        .when((pl.col("abs_ret_ratio") <= 0.75) & (pl.col("range_ratio") <= 0.85))
        .then(pl.lit("波动明显收缩"))
        .otherwise(pl.lit("波动结构变化"))
        .alias("vol_note"),
        pl.when((pl.col("up_ratio_after") - pl.col("up_ratio_before")) >= 0.08)
        .then(pl.lit("上涨占比提高"))
        .when((pl.col("up_ratio_after") - pl.col("up_ratio_before")) <= -0.08)
        .then(pl.lit("上涨占比下降"))
        .otherwise(pl.lit("涨跌占比变化不大"))
        .alias("direction_note"),
        pl.when(pl.col("up_range_ratio") > pl.col("down_range_ratio") * 1.2)
        .then(pl.lit("上行波动相对增强"))
        .when(pl.col("down_range_ratio") > pl.col("up_range_ratio") * 1.2)
        .then(pl.lit("下行波动相对增强"))
        .otherwise(pl.lit("上下行波动同步变化"))
        .alias("range_note"),
    )
    .with_columns(
        pl.concat_str("vol_note", "direction_note", "range_note", separator="；").alias("summary")
    )
    .select(
        "peak_date",
        "cut_date",
        "scale",
        pl.col("score").round(3).alias("score"),
        pl.col("persistence").round(2).alias("persistence"),
        pl.col("abs_ret_ratio").round(2).alias("abs_ret_ratio"),
        pl.col("range_ratio").round(2).alias("range_ratio"),
        pl.col("up_ratio_before").round(2).alias("up_ratio_before"),
        pl.col("up_ratio_after").round(2).alias("up_ratio_after"),
        pl.col("up_range_ratio").round(2).alias("up_range_ratio"),
        pl.col("down_range_ratio").round(2).alias("down_range_ratio"),
        pl.col("volume_delta").round(2).alias("volume_delta"),
        "summary",
    )
    .sort("peak_date")
)

2017-12-25 2017-11-27 21x21 短尺度峰，说明变化集中在约一个月级别。分数 6.50，persistence=0.60，不是全尺度最强冲击，但已经足够异常。辅助表显示前后波动结构发生变化，适合检查短周期策略在这一段前后的盈亏分布是否换挡。
2019-06-14 2019-05-10 42x21 中短尺度峰，分数 5.66，强度低于 2020、2021、2022 的大峰，但历史分位很高。它更像一段局部市场结构切换，适合观察品种间强弱扩散、趋势持续性和反转策略胜率是否同步改变。
2020-02-05 2019-12-24 63x21 峰，分数 12.21，persistence=1.00。这说明多个尺度同时认为状态差异显著，是非常典型的全市场级别变化。辅助表显示波动明显放大，这类阶段对持仓过长、止损较宽、依赖平稳波动假设的策略影响通常很大。
2020-12-14 2020-10-16 126x42 峰，分数 6.26。最佳尺度偏长，说明它不是单日冲击，而更像几个月维度的市场结构切换。遇到这种点，应重点检查策略参数是否对长期波动水平、趋势长度、回撤恢复速度过于敏感。
2021-10-25 2021-09-16 42x21 峰，分数 13.69，是本次默认结果中最强的一次。persistence=0.80 表明大部分尺度都支持这个变化。辅助表显示波动显著放大，上下行振幅也同步抬升。对策略来说，这通常意味着入场过滤、止盈止损、持仓周期都可能需要重新评估。
2022-04-18 2022-03-17 21x21 峰，分数 11.26，短尺度但强度很高。辅助表显示从前一段高波动状态切到相对收缩状态，说明 regime change 不只包括“波动变大”，也包括“波动从异常高位回落”。这类阶段下，追趋势策略可能失去此前的波动推动，均值回归策略可能重新变得可用。
2024-12-17 2024-10-21 63x42 峰，分数 8.22。这是一个中等偏长尺度的变化，说明前后两段市场横截面分布出现明显差别，但不是 2021 那种极端全尺度冲击。适合重点观察策略是否从单品种有效变成多品种同步有效，或者反过来从普遍有效变成只在少数品种有效。

这些解释只基于数据里的价格、波动、上下行振幅和成交变化特征。它们不强行给出宏观事件标签，因为同一个日期附近可能有多个市场因素同时作用。更稳妥的做法是：先用算子找出结构变化日期，再回到策略信号、持仓、品种贡献和交易明细里逐段排查。

10. 参数怎么调

常用参数可以按下面方式理解。

参数 调大时的效果 调小时的效果
scales 更容易关注较长结构变化，但确认更慢 更敏感，能看到短期冲击，但噪声更多
baseline_window 标准化参考更长，分数更稳 更快适应近期市场，但历史可比性下降
min_baseline 更严格，前期不容易出分 更早出分，但早期标准化不稳定
z_thre 候选峰更少 候选峰更多
rank_thre 要求必须处在更极端历史分位 更容易放出候选
persistence_thre 要求更多尺度同时异常 单一尺度异常也更容易通过
scale_z_thre 单尺度进入 persistence 更难 persistence 更容易升高
min_peak_distance 峰更稀疏，确认更慢 峰更密集，确认更快
top_k 综合更多尺度，结果更平滑 更依赖最高分尺度，结果更尖锐
min_contracts 每天至少需要更多合约参与，横截面更稳 可用日期更多，但样本质量可能下降

如果目的是做长期市场分段，通常应该提高 min_peak_distance、保留多个尺度，并关注 confirmed_peak_score。如果目的是做实时风控预警，可以同时观察 peak_score 和 is_peak_candidate，但要接受候选峰后续可能被同一簇里的更高点替代。

11. 使用建议

daily_market_change_peak_score 更适合放在策略研究流程的上游：

  1. 先用全市场日线数据计算 regime 点；
  2. 再把策略回测结果按这些日期切段；
  3. 分别比较每段的收益、回撤、交易次数、平均持仓、胜率、品种贡献；
  4. 如果某个策略只在某个 regime 后有效，需要检查它依赖的是趋势延续、波动扩张、波动收缩、成交活跃度，还是品种间相关性变化；
  5. 如果多个策略在同一个 regime 点前后同时失效，说明更可能是市场结构变化，而不是单个策略参数偶然失效。

最重要的是：不要把 confirmed_peak_score 当成方向信号。它只告诉你“变化很强”，不告诉你应该做多还是做空。方向和交易动作仍然要回到具体策略信号、风险控制和持仓逻辑里判断。
